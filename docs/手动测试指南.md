# 0.5.17 新功能手动测试指南

本文只写 `0.5.0` 至 `0.5.17` 新功能的手动测试操作。W0、P0、F0-F3、F5-F9 可以逐项单独测试，不要求一次全部完成；F4 已取消实现，不需要手动测试。

## 开始前

1. 会修改或扣减库存的测试先执行 `元器件库存 -> 另存库存备份`，或只使用可删除的临时记录。
2. 每节开始前关闭同类旧面板，在库存总览点击顶部的“清除筛选”。该按钮会同时清除搜索、分类、库存、补货、收藏和 EDA 模型筛选。
3. 文中的 `<C_A>`、`<C_B>` 等必须替换成实际 C 编号。同一测试内 A、B、C、D、M、X 的 C 编号要互不相同，且库存中不能有其他同 C 编号记录。
4. `F0-已用完`、`F0-无模型` 允许不填 C 编号，因为它们只用于验证不可放置状态；其余样本使用有效 C 编号。

## 测试文件和目录怎样建立

文中的 CSV 代码块是“文件内容”，不是要在 EDA 或 PowerShell 中执行的命令。Windows 下统一按以下方法准备，后文只再写文件名和该文件需要替换的占位符：

1. 在资源管理器打开工程根目录的 `logs`。没有 `manual-test-input` 文件夹时，在 `logs` 中新建该文件夹；后文的手工 CSV、JSON 和测试目录都放在 `logs\manual-test-input`。`logs` 已被 Git 忽略，不会混入源码提交。
2. 从开始菜单打开“记事本”，把指定代码块中从表头到最后一行的内容原样粘贴进去，不要复制代码块外的说明，也不要使用 Word。
3. 按该小节要求替换全部 `<C_...>`。例如把 `<C_A>` 连同尖括号一起替换为实际编号 `C17168`；保存前搜索 `<`，确认没有任何占位符残留。不要把英文逗号改成中文逗号。
4. 在记事本执行“文件 -> 另存为”，进入 `logs\manual-test-input`，文件名填写小节指定的 `.csv` 名称，“保存类型”选择“所有文件 (*.*)”，“编码”选择 `UTF-8`，再点击保存。
5. 在资源管理器开启“查看 -> 显示 -> 文件扩展名”，确认文件不是 `文件名.csv.txt`。若误存为 `.txt`，先显示扩展名，再把它改成 `.csv`。
6. 需要选择一份文件时，在 EDA 的系统文件选择器中单击该文件并点“打开”；需要同时选择两份文件时，在同一个选择器中按住 `Ctrl` 依次单击两份文件，再点“打开”。

CSV 进入“BOM 列映射”后，先核对“表头候选”为第 `1` 行、“表头行”为 `1`，再按小节给出的对应关系设置字段。下拉选项会显示成 `A: 表头名`、`B: 表头名`；不需要的字段选择“留空 / 不映射”。最后检查“原始行预览”，点击底部“确定”。映射窗口点“取消”或直接关闭只会结束当前流程，不会修改库存。

## 这些状态怎样建立

以下名称中，只有“数量类型”是表单选项；模型状态和补货状态都是保存后由插件计算出来的，不能在表单里直接选择。

| 要建立的状态 | 实际操作 |
| --- | --- |
| 真实数量 | 新增表单的“数量类型”选择“真实数量”，再填写数量 |
| 大概数量 | 新增表单的“数量类型”选择“大概数量”，再填写数量 |
| 数量未知 | 只能在新增表单选择“数量未知”；数量输入框随后禁用 |
| 已用完 | 新增表单选择“已用完”，或在“完整编辑”勾选已用完 |
| EDA 模型可用 | 新增表单填写 C 编号后点击“查询 EDA 器件模型”，看到已找到模型，再保存 |
| 模型缺失 | 点击“查询 EDA 器件模型”，看到系统库暂无对应模型，再保存 |
| 尚未查询 | 不点击“查询 EDA 器件模型”，直接保存 |
| 低于最低库存 | 真实数量小于最低库存，例如数量 `1`、最低库存 `3` |
| 可能需要补货 | 大概数量小于最低库存，例如大概 `2`、最低库存 `3` |
| 需要盘点 | 新增时同时选择“数量未知”并填写最低库存，例如最低库存 `3` |

新增表单的“名称”为必填项。通过 C 编号查询到模型后通常会自动带出名称；没有带出时要手工填写。

当前“完整编辑”只有“真实数量”和“大概数量”，没有“数量未知”。因此未知数量记录必须在新增时一次填好最低库存，后续不要用“完整编辑”保存它。这是当前已确认的功能缺口，不是测试者漏看了选项。

## W0：库存总览移动、折叠与恢复

入口：首页、SCH 或 PCB 的 `元器件库存 -> 库存总览`，不需要准备测试数据。

在结果备注中记录本次使用 Web 端还是桌面端及客户端版本；本轮只测试当前环境，另一环境单独记录。

1. 打开库存总览，输入任意搜索词或选择一个分类，记住当前状态。
2. 按住宿主标题栏拖动窗口：先短距离移动一次，再按住约 `3` 秒后移动并松开。两次操作中总览都不得隐藏或关闭。
3. 点击 EDA 空白画布一次。总览仍应保持可见，不得把普通失焦误判成隐藏命令。
4. 点击宿主标题栏的最小化按钮。库存正文应折叠，但原宽标题栏仍留在页面上；恢复后，第 1 步状态应完整保留。
5. 再点击最大化并恢复普通尺寸；标题栏和正文都不应消失，页面内容仍可滚动使用。

通过标准：移动窗口、点击画布、最小化、恢复和最大化都不会让总览消失，恢复后浏览状态不变。“放置”主动隐藏和失败恢复由 F0 单独验证。

最终结论（2026-07-25，`0.5.16` 详细日志版）：通过。用户已完成移动窗口、点击画布、最小化与恢复、最大化与恢复检查，窗口没有异常隐藏或关闭，恢复后浏览状态保持不变。

## 公共测试数据

每节只准备自己会用到的记录，不需要一次建齐。

| 代号 | 新增表单填写内容 | 其他要求 |
| --- | --- | --- |
| A | 名称 `测试-A`，真实数量 `10` | F0 前查询并绑定模型；放入分类“手动测试” |
| B | 名称 `测试-B`，真实数量 `1` | 最低库存先留空 |
| C | 名称 `测试-C`，大概数量 `2` | 最低库存先留空 |
| D | 名称 `测试-D`，数量未知，最低库存 `3` | 必须在新增时一次建好 |
| S | 名称 `测试-S`，真实数量 `6` | 只用于 F9 替代料 |
| M | 不创建库存记录 | EDA 画布或外部 BOM 中存在该 C 编号 |
| X | 不要求库存记录 | 使用与 A-D 不同的有效 C 编号和 EDA 模型，并把 EDA 原生“加入BOM”设为“否” |

第一次准备 A-D 时按以下操作执行：

1. 打开库存总览，点击左上角分类图标并进入“管理分类”。“手动测试”不存在时，点击一级分类栏的 `+` 新建；已经存在时直接复用。新增表单只能选择已有分类，不能在表单中临时创建。
2. 在 EDA 自带器件库中选取 A、B、C、D 四个不同模型，记下各自 C 编号。对每个编号都先在库存总览把搜索范围选为“全部分类”，输入完整 C 编号并点击搜索：首次准备只使用结果为 `0` 条的编号；重测时若恰好已有一条状态正确的测试记录，直接复用，不要重复新增。
3. 只对尚未建立的记录执行 `元器件库存 -> 按立创 C 编号添加`，填写 C 编号和上表内容。A 必须点击“查询 EDA 器件模型”并确认查询成功，再选择一级分类“手动测试”；B、C、D 不要求绑定模型。
4. 保存后先在库存总览 A 所在行确认“分类”列为“手动测试”，再逐条点击“查看详情”：A 的数量为 `10`、数量类型为“真实数量”、EDA 模型为可用；B 的数量为 `1`、数量类型为“真实数量”；C 的数量为 `2`、数量类型为“大概数量”；D 的数量和数量类型均为“数量未知”，最低库存为 `3`。

## F0：从库存总览放置元器件

入口：原理图的 `元器件库存 -> 从库存放置元器件`

### 前置条件

1. 打开可编辑的 SCH；A 为真实数量 `10`、模型可用、分类为“手动测试”。
2. 执行 `添加自定义元器件`，填写名称 `F0-已用完`，C 编号留空，数量类型选择“已用完”后保存。
3. 再执行 `添加自定义元器件`，填写名称 `F0-无模型`，C 编号留空，选择“真实数量”并填 `1`，不要查询模型，直接保存。
4. 关闭已经打开的库存总览。

### 测试步骤

1. 执行入口。新打开的总览应默认只显示“有库存 + 模型可用”的记录，不出现逐条原生单选列表。
2. 先在搜索框输入 A 的完整 C 编号并点击搜索，确认能定位 A；随后点击“清空搜索”，再打开分类栏选择“手动测试”，重新确认 A 可见。搜索和分类必须分开验证。
3. 不要点击 A 的名称；直接在 A 所在行的“操作”列点击第一个“放置”按钮。总览应主动隐藏，器件绑定到鼠标；在 SCH 画布点击一次完成放置。
4. 执行普通的 `元器件库存 -> 库存总览` 并点击“清除筛选”。先确认结果摘要中的筛选结果数等于库存总数；库存超过一页时，两个样本不保证同时出现在第一页。随后分别搜索完整名称 `F0-已用完` 和 `F0-无模型`：对应行的“放置”按钮均应禁用，悬停按钮可分别看到库存已用完或没有可用 EDA 模型的原因。
5. 核对 A 和两个负向样本的库存数量都没有变化。

通过标准：可在总览中搜索、按分类选择并放置；成功后面板不挡住画布；不可放置项给出原因；放置不自动扣库存。

最终结论（2026-07-25，`0.5.16` 详细日志版）：通过。搜索、分类选择和 A 放置均已完成实测，总览按预期让出画布；修订步骤 4 后，用户分别搜索并确认 `F0-已用完` 与 `F0-无模型` 的“放置”按钮均禁用，悬停提示分别为库存已用完和没有可用 EDA 模型。诊断日志 `jlceda-inventory-diagnostics-2026-07-25T14-05-35-281Z.json` 记录普通总览加载全部 `90` 条库存并正常关闭，本次会话无 `warn/error`；最终 schema `9`、revision `121` 库存中 A=`10`、`F0-已用完=0`、`F0-无模型=1`，确认放置和检查均未自动扣减库存。

收尾：删除 `F0-已用完` 和 `F0-无模型`。

## P0：自动备份与恢复

入口：`另存库存备份 / 自动备份设置 / 恢复库存备份`

### 前置条件

1. 确认 A=`10`、B=`1`，并记下两者的实际 C 编号。
2. 在 `logs\manual-test-input` 中新建空文件夹 `p0-dir-1` 和 `p0-dir-2`，分别作为“目录一”和“目录二”。只使用这两个没有重要文件的测试目录；固定备份会在其中创建或覆盖 `jlceda-inventory-latest.json`。
3. 先执行一次“恢复库存备份”但不要确认恢复。有旧恢复点时，来源列表会出现“上次恢复前快照”；该快照会在本节第一次实际恢复时被替换，而且当前 UI 无法导出或还原旧快照。旧快照仍有价值时立即取消并停止 P0；确认可以覆盖时再继续。只有外部文件选择器时直接点取消。
4. 打开一次“自动备份设置”。已有配置时，窗口会显示“状态”和“路径”，把它们记在测试记录中：原状态已启用时，先取消，再重新打开设置并选择“停用自动备份”，防止第 1-3 步覆盖原固定备份；原状态未启用时直接取消。从未配置时会直接打开目录选择器，点取消，并记录为“原状态未启用、无历史目录”。

原生目录选择只在已开启“允许外部交互”的桌面端可用。后面需要核对 JSON 时，用记事本或代码编辑器打开文件，搜索 B 的实际 C 编号；它附近的 `quantity` 应为当前数量，文件顶部的 `revision` 和 `updatedAt` 应随保存更新。

### 测试步骤

1. 执行“另存库存备份”，在 `logs\manual-test-input` 保存 `p0-original.json`。
2. 在库存总览搜索 A，执行“完整编辑”，把数量改成 `7`。执行“恢复库存备份”；出现来源列表时选择“选择 JSON 备份文件”，再选择 `p0-original.json`。核对“即将用备份完整替换当前库存”摘要中的来源、条目数和 revision 后点确定，A 应回到 `10`。
3. 再执行“恢复库存备份”，选择“上次恢复前快照”。同样核对完整替换摘要并点确定，A 应回到 `7`；随后把 A 手工恢复为 `10`。
4. 只有从未配置过自动备份时才测首次分支：打开“自动备份设置”应直接出现 EDA 原生目录选择器。先取消，设置不变且不报错。已经配置过的账号把此步记为“不适用”。
5. 再打开设置并选择目录一。目录中应自动生成 `jlceda-inventory-latest.json`，用户不需要手建 JSON；打开该文件，顶部应有 `"schemaVersion": 9`。
6. 再打开设置，选择“选择备份目录”。第一次取消时应继续使用目录一；再次打开设置并选择“选择备份目录”，改选目录二后，应在目录二创建固定 JSON。
7. 把 B 从 `1` 改为 `2`，固定 JSON 中的 B 应自动变为 `2`，过程不弹窗。
8. 打开设置并执行“立即测试备份”，应成功且本次设置命令结束。再次打开“自动备份设置”，选择“停用自动备份”；把 B 从 `2` 改为 `3`，固定 JSON 仍应是 `2`。
9. 打开设置并选择“使用当前文件重新启用”，固定 JSON 应立即变为 B=`3`。再把 B 依次改为 `4`、`5`，每次都应更新 B、`revision` 和 `updatedAt`。
10. 保持自动备份启用，执行“另存库存备份”，在 `logs\manual-test-input` 保存为 `p0-current.json`；把 A 改为 `6` 后执行“恢复库存备份”，选择“选择 JSON 备份文件”和 `p0-current.json`，核对完整替换摘要后确定。恢复完成后再另存为 `p0-compare-file-restore.json`，它与 `p0-dir-2\jlceda-inventory-latest.json` 的库存内容、`revision`、`updatedAt` 应一致。
11. 再执行“恢复库存备份”，选择“上次恢复前快照”，核对摘要后确定，A 应回到 `6`；再次另存为 `p0-compare-recovery-restore.json`，它与 `p0-dir-2\jlceda-inventory-latest.json` 也应一致。
12. 在 EDA 的 `高级 -> 扩展管理器 -> 已安装 -> 元器件库存` 临时关闭“允许外部交互”，再打开自动备份设置并选择备份目录，应提示重新授权且不改变原设置。恢复该权限后，再打开目录选择器并点取消，确认仍可打开且取消不改配置。Web 端只需确认固定目录不受支持，手动另存和恢复仍可用。

第 10、11 步可以用 SHA-256 避免肉眼比较整份 JSON：在资源管理器进入 `logs\manual-test-input`，点击地址栏输入 `powershell` 并回车，然后分别执行以下命令。每条命令输出的两个 `Hash` 必须相同；不同就表示该步失败，再打开两份 JSON 定位差异。

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath '.\p0-dir-2\jlceda-inventory-latest.json', '.\p0-compare-file-restore.json'
Get-FileHash -Algorithm SHA256 -LiteralPath '.\p0-dir-2\jlceda-inventory-latest.json', '.\p0-compare-recovery-restore.json'
```

通过标准：不填写路径、不手建 JSON；取消无副作用；停用后文件不更新；自动备份启用时，每次库存保存或恢复后固定 JSON 都与当前库存一致。

## F1：当前设计与外部 BOM 库存校验

两个入口彼此独立：

- SCH/PCB 的 `校验当前设计库存` 读取当前设计，不打开文件选择器。
- 首页、SCH、PCB 的 `校验外部 BOM 库存` 会打开文件选择器，不读取或放置画布器件。

### F1-A：校验当前设计库存

前置条件：A=`真实 10`、B=`真实 1`、C=`大概 2`、D=`数量未知`；四条记录不能有同 C 编号重复库存。

X 的建立方法：从 EDA 自带器件库另选一个与 A-D、M 都不同的模型，记下其 C 编号并放入测试 SCH。确认选中该器件后，右侧属性面板存在 EDA 原生“加入BOM”属性；X 不需要插件库存记录。宿主不提供该属性时，按下方步骤把 X 分支记为未覆盖。

   | A | 总需求 `4`，状态“充足” |

通过标准：实际建立的每个分支需求和状态正确。未建立 M 或 X 时只能把对应分支记为“未覆盖”，不能记整项完整通过。

### F1-B：校验外部 BOM 库存

本节使用首页、SCH 或 PCB 的 `元器件库存 -> 校验外部 BOM 库存`，不是 F1-A 的“校验当前设计库存”。该入口只读取稍后选择的 BOM 文件，不读取当前画布；因此不需要 X，也不需要在画布放置任何器件。

#### 刚完成 F1-A 时怎样复用

如果已经按本指南完成 F1-A，并且之后没有修改 A-D 的库存，也没有为 M 新增库存，可以直接复用，不要再次创建元器件。开始 F1-B 前只做一次快速复核：

1. 在库存总览把搜索范围设为“全部分类”，分别用完整 C 编号搜索 A、B、C、D，确认每个编号只有一条完全相同的记录；打开详情确认 A=`真实数量 10`、B=`真实数量 1`、C=`大概数量 2`、D=`数量未知`。
2. 搜索 M 的完整 C 编号，确认没有 C 编号完全相同的库存记录。M 在 F1-A 画布中有器件、但插件库存为 `0` 条，正好就是 F1-B 需要的“库存缺失”样本。
3. X 不会写入本节 CSV，也不会被外部 BOM 入口读取，直接忽略。

以上三项都成立时，跳过下面“库存准备”，直接建立 `f1-stock-check.csv`。任一项不成立时，不能沿用旧的 F1-A 结果；按下一节重新选择不会影响真实库存的 C 编号。

#### 为什么要准备这些库存

F1-B 要用同一份 BOM 一次覆盖五种库存判断。表中的库存不是随便准备的数据，每条都用于触发一个确定结果：

| 代号 | BOM 单板数量 | 板数 | 总需求 | 插件库存必须是 | 要验证的结果 |
| --- | ---: | ---: | ---: | --- | --- |
| A | `2` | `2` | `4` | 真实数量 `10` | 充足 |
| B | `1` | `2` | `2` | 真实数量 `1` | 不足，缺口 `1` |
| C | `1` | `2` | `2` | 大概数量 `2` | 需复核 |
| D | `1` | `2` | `2` | 数量未知 | 需盘点 |
| M | `1` | `2` | `2` | 没有任何同 C 编号库存记录 | 库存缺失 |

库存校验会合并同一 C 编号的全部库存记录，所以准备前必须搜索。例如 B 如果还有另一条同 C 编号的真实库存 `1`，合计库存会变成 `2`，结果将从“不足”变成“充足”；M 只要存在任意一条同 C 编号记录，即使该记录已用完，也不会得到“库存缺失”。最低库存、分类、EDA 模型状态和记录名称不参与上述五种判断。

#### 库存准备

只有无法复用 F1-A 数据、或打算单独执行 F1-B 时才需要本节。

1. 选择五个互不相同的有效 C 编号，分别记为 `<C_A>`、`<C_B>`、`<C_C>`、`<C_D>`、`<C_M>`。
2. 在库存总览把搜索范围选为“全部分类”，逐个输入完整 C 编号并点击“搜索”。完整 C 编号的精确匹配会排在最前；即使还出现前缀或名称包含该数字的其他结果，也只检查是否存在 C 编号完全相同的记录。
3. 按搜索到的“同 C 编号记录数”决定是否可用：

   | 同 C 编号记录数 | A-D 的处理 | M 的处理 |
   | ---: | --- | --- |
   | `0` 条 | 可以使用该编号，并按下表新建一条临时库存 | 可以使用；保持为 `0` 条，不要新增库存 |
   | `1` 条 | 打开详情核对。只有数量类型和数量与下表对应项完全一致时才可直接复用；来源是以前的测试记录还是现有真实记录不影响判断 | 不可使用，因为 M 必须没有库存记录 |
   | `2` 条及以上 | 不可用于本受控测试；校验会合并这些记录 | 不可使用 |

   “不可使用”表示换一个 C 编号，不是删除、修改或合并现有真实库存。现有真实记录若唯一且状态恰好符合，可以只读复用；若不符合，不能为了凑测试条件把真实数量或数量类型改掉。

4. 对搜索结果为 `0` 条、需要新建的 A-D，分别执行 `元器件库存 -> 按立创 C 编号添加`。名称为必填项，按下表填写；本节不要求点击“查询 EDA 器件模型”。

   | 代号 | 名称 | 数量类型 | 数量 | 最低库存 | 不能替代成 |
   | --- | --- | --- | ---: | --- | --- |
   | A | `测试-A` | 真实数量 | `10` | 留空 | 大概数量、数量未知或其他数值 |
   | B | `测试-B` | 真实数量 | `1` | 留空 | 真实数量 `2` 及以上、大概数量或数量未知 |
   | C | `测试-C` | 大概数量 | `2` | 留空 | 只填数字 `2` 的真实数量记录 |
   | D | `测试-D` | 数量未知 | 不填写，输入框会禁用 | 留空或 `3`，不影响本节 | 真实数量 `0`、`50` 或大概数量 |

5. 新建或复用后逐条打开“查看详情”，确认 A=`真实数量 10`、B=`真实数量 1`、C=`大概数量 2`、D=`数量未知`，并确认每个 C 编号都只有这一条库存。如果 D 不是未知数量，只删除本节新建的错误临时记录后从新增表单重建；不要删除现有真实记录，“完整编辑”也不能把它改成未知。
6. `<C_M>` 只用于制造“BOM 有需求、插件库存中没有记录”的分支。再次用完整 C 编号搜索，确认没有 C 编号完全相同的库存记录；不要为 M 新增库存。

## F2：最低库存与补货筛选

入口：`库存总览 -> 完整编辑`，以及总览顶部“补货状态”

前置条件：A=`真实 10`、B=`真实 1`、C=`大概 2`，三者最低库存留空；D 必须已经按公共数据方法建成“数量未知 + 最低库存 3”。

2. 点击“清除筛选”，核对状态原文：A“库存充足”、B“低于最低库存”、C“可能需要补货”、D“需要盘点”。
3. 对 A 执行“完整编辑”，把数量改为 `0`，不要勾选“已用完”，保存后 A 应显示已用完。固定使用这一种操作，避免不同测试者走两条分支而得到不可比较的结果。
4. “补货状态”选择“需要补货”，结果中应包含 A、B、C 且不包含 D；其他真实库存中的补货记录可以同时存在。
