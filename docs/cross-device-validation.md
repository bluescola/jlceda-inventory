# 跨设备验证清单

官方文档没有定义扩展用户配置的跨设备行为。`0.5.16` 已在同账号、同电脑上确认 Web 与桌面宿主各自维护独立库存，不会自动传播；桌面客户端之间、不同物理设备和账号隔离仍需按以下矩阵验证，并记录客户端版本、时间和传播延迟。

| 测试 | 预期观察 | 结果 |
| --- | --- | --- |
| Web 端 A 添加库存，桌面端 B 打开库存 | 条目出现，并记录传播延迟 | 当前宿主不传播：Web 完整恢复后为 revision `1`，桌面重开仍为 revision `131` |
| 桌面端 B 修改另一条库存，Web 端 A 重新打开库存 | 不重装扩展即可看到修改 | 当前宿主不传播：桌面已有 `90` 条库存时，首次 Web 导出仍为 revision `0`、库存 `0` 条 |
| A、B 同时在线并编辑同一条目 | 记录冲突表现和最终胜出值 | 待验证 |
| A 离线编辑后重新联网 | 记录恢复行为和最终胜出值 | 待验证 |
| 切换到另一账号 | 不同账号的库存相互隔离 | 待验证 |
| 卸载后以相同 UUID 重装 | 记录数据是否保留 | 待验证 |
| 使用相同 UUID 升级扩展 | 既有库存仍可读取 | 待验证 |
| 分别保存 100、1000 和 5000 条库存 | 记录容量、延迟和写入失败情况 | 待验证 |

2026-07-26 的同机跨运行时结论：Web 固定目录能力以“非客户端环境”明确拒绝，但手动另存可用。将桌面 schema `9`、revision `131` JSON 完整恢复到空 Web 存储后，Web 生成本地 revision `1`，`90` 条库存及所有分类、订单批次、流水和出库批次均完整迁移；除 revision 与更新时间外，全部顶层数据与来源一致。随后重开桌面仍为 revision `131`，固定备份 Hash 未变。因此 Web/桌面之间只能使用 JSON 显式迁移，不能依赖 `SYS_Storage` 自动同步；该结论不替代两台桌面客户端或不同物理设备的剩余验证。

以下官方 BETA 能力也需要分别在 Web 端和桌面端验证：

- 查询有效、无效和重复的 C 编号；
- 导入到个人库，验证已存在器件不会重复复制，并验证复制结果可从个人库回读；
- 导入带中文文件名的立创商城真实 `.xls` 订单详情，并分别回归 `.xlsx`、UTF-8 CSV 和 JSON；
- 确认 Web 与桌面端均能跳过空白/隐藏模板工作表，正确读取带“个”单位的数量，且不会重复导入同一订单页；
- 同时选择多个订单，确认预览中的订单号、行数、数量和预计变化正确；再次选择相同文件或同订单号的重新导出文件时，应显示历史导入时间并保持库存数量不变；
- 在一台设备完成批量导入后，从另一设备查看 schema-v9 文档中的订单关联、BOM 流水、项目快照、采购记录和替代关系能否随库存一起出现；删除部分订单库存后，再验证另一设备可以只恢复缺失物料；
- 分别在 SCH 与 PCB 打开当前设计库存校验，验证器件读取、板数倍率、无 C 编号行和外部 BOM 降级；
- 单选器件时验证唯一库存会翻页、滚动并高亮；保持总览最小化或隐藏后换一组多选器件再次定位，验证旧会话被新选择替换、全部匹配库存一次显示、库存 ID 去重；部分未匹配时独立警告必须列出具体器件，清除筛选后警告消失并恢复完整库存；
- 使用相同语义 BOM 的原文件和重新导出文件验证重复出库阻止，再明确确认新生产批次并整批撤销；活动批次引用条目应禁止删除或作为会消失的合并源；
- 捕获、重同步和删除项目快照，新增/删除采购记录，并验证采购历史的快照 ID 审计引用；
- 建立和删除用户确认的替代关系，验证候选排序但不影响库存校验或 BOM 扣减；
- 从原理图菜单打开库存总览，搜索或按分类选择有库存且模型可用的元器件，确认总览隐藏后完成鼠标放置且库存不自动扣减；
- 确认绑定元器件到鼠标不会自动扣减库存；
- 桌面端指定路径备份失败时不影响 EDA 主存储；
- 桌面端恢复写入失败时不覆盖此前的恢复点；损坏的内部恢复点不阻断外部 JSON 恢复；
- Web 端不支持直接路径写入时仍可使用“另存库存备份”保存独立快照。

现有 Web/桌面验证已经失败于自动传播，应继续把 EDA 用户配置视为当前宿主的运行时主存储，并依靠 JSON 备份完成恢复和显式迁移，不得把该能力描述为“已同步”。其余矩阵仍用于确定桌面客户端之间、账号隔离、重装升级、并发和容量边界；可靠的自动同步需要独立后端或未来官方提供的云存储 API。
