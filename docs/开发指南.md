# 开发指南

**简体中文** | [English](https://github.com/bluescola/jlceda-inventory/blob/main/docs/development-guide.md)

本文是 JLCEDA Inventory 的开发入口，说明本地环境、验证命令、工程边界和发布检查。具体架构决策、数据格式和宿主验收记录通过文末链接维护，避免多份文档重复描述后产生分叉。

## 环境准备

- Node.js 版本不得低于 `20.17.0`；CI 当前使用 Node.js 24。
- 使用 npm 和仓库中的 `package-lock.json` 安装确定版本的依赖。
- 涉及嘉立创 EDA API、IFrame、文件系统或鼠标放置的改动，需要在嘉立创 EDA 专业版 V3 Web 端或桌面客户端进行对应实测。

首次拉取或依赖变化后执行：

```powershell
npm ci
```

不要使用会改写锁文件的安装方式替代 `npm ci`，除非本次任务本身就是经过评审的依赖升级。

## 常用验证命令

```powershell
npm run lint
npm run typecheck
npm test
npm run build
```

- `npm run lint` 检查代码规范和常见静态问题。
- `npm run typecheck` 执行严格 TypeScript 类型检查，不生成文件。
- `npm test` 运行领域逻辑、平台适配器、IFrame 协议和发布元数据测试。
- `npm run build` 编译宿主入口及 IFrame 资源，并生成可上传的 `.eext` 扩展包。

代码变更提交前应依次完成以上四项。纯文档变更至少执行 `git diff --check`；CI 仍以完整验证结果为准。自动化结果与 Web、桌面或物理设备实测必须分别记录，不得把未执行的宿主手测写成“通过”。

## 构建产物

- `dist/` 是嘉立创 EDA 宿主入口的编译结果。
- `iframe/` 是各 IFrame 页面编译和内联资源后的结果。
- `build/dist/` 中的 `jlceda-inventory_v<version>.eext` 是最终上传包。
- `extension.json` 的入口保持为 `./dist/index`，宿主产物保持官方 SDK 要求的单一 IIFE 输出和 `edaEsbuildExportName` 约定。

根目录 `dist/` 与 `iframe/` 均为生成结果，不要手工编辑。IFrame 源码位于 `src/platform/jlceda-v3/iframe`。`build/` 与 `config/` 继承官方 SDK 基线，除升级基线或修复构建问题外不要调整其结构。详细版本和升级要求见[官方 SDK 基线](official-baseline.md)。

## 目录与依赖边界

| 路径 | 职责 |
| --- | --- |
| `src/features/` | 平台无关的领域模型、应用服务和端口 |
| `src/platform/jlceda-v3/` | 嘉立创 EDA V3 API 适配、持久化、IFrame 和展示层 |
| `src/index.ts` | 官方扩展唯一源码入口 |
| `locales/` | 运行时及 `extension.json` 的中英文资源 |
| `tests/` | 单元测试、适配器契约和发布约束测试 |
| `docs/` | 架构、数据格式、决策和验收说明 |

`src/features` 不得引用全局 `eda`、`ILIB_*` 或其他宿主类型。官方 API 调用必须集中在 `src/platform/jlceda-v3`，业务层通过已有端口和应用服务访问平台能力。新增功能应优先复用既有领域服务、仓储端口、平台适配器和测试夹具。完整依赖方向和模块职责见[架构说明](architecture.md)。

## 数据与安全约束

- `inventory.v1.document` 是版本化库存主文档。schema 迁移必须保留条目 ID、数量、分类、历史、引用和 revision 语义。
- 所有库存写入必须经过领域服务、容量预算和 revision 校验；IFrame 只能提交用户意图，不得直接写仓储。
- 只有 EDA 主存储成功后才能刷新自动备份。备份、状态保存或通知失败不得回滚已经成功的库存写入。
- 完整恢复必须先校验、再预览、后确认；主恢复失败时必须保留并还原恢复点。非法、未来 schema 或超容量文档应在写入前拒绝。
- Web 与桌面主库存是独立状态，只能通过 JSON 显式迁移，不得描述为自动同步。
- 文件、BOM、订单、二维码、URL、商城字段和 IFrame 消息均是不可信输入。解析和分配前应执行文本清理、格式校验、容量限制和一次性操作 ID 校验。
- 不提交真实库存导出、订单信息、诊断日志、测试备份、凭据、个人绝对路径或其他用户数据。

持久化、备份和恢复细节见[架构说明](architecture.md)与[可靠性路线](roadmap.md)；跨运行时和跨设备结论见[跨设备验证清单](cross-device-validation.md)。

## 平台适配

宿主沙箱不保证存在浏览器全局 `URL`、`structuredClone` 或可用的 `fetch`。解析、复制和外部交互应使用工程已有的内置实现与平台适配器，不能在领域层假设标准浏览器环境。

器件库、分类树、文件选择、文件系统、SCH/PCB 读取、IFrame 和鼠标放置等能力包含 BETA API。新增或修改这些链路时应做到：

1. API 调用只出现在 `src/platform/jlceda-v3`。
2. Web 与桌面能力不同的地方提供明确、用户可理解的降级或拒绝行为。
3. IFrame 消息继续校验协议版本、请求作用域、会话和操作 ID，避免过期响应或重复写入。
4. 长生命周期总览收到后台快照时只更新数据，不重置搜索、分类、筛选、排序、页码、勾选项、滚动和焦点。
5. 自动化测试不能替代实际宿主对 API 可用性、窗口层级、文件权限和鼠标交互的验证。

已确认的平台隔离、兼容问题和降级路线见[架构说明](architecture.md)；具体 UI 边界见[库存总览、分类管理与子窗口边界](inventory-overview-boundary.md)和[元器件统一添加表单与窗口层级边界](component-entry-boundary.md)。

## 自动化与宿主实测

测试覆盖应随风险和行为变化扩展。库存、订单、BOM、项目规划、备份或恢复改动至少检查受影响的成功、取消、失败、重复、超限、旧数据迁移和回滚分支。涉及写入时，还应验证 revision、原子性、幂等性、容量预算以及失败后的主数据状态。

宿主实测应记录宿主版本、Web 或桌面环境、测试数据前提、实际结果和仍未验证的分支。不得在包含真实库存的环境中故意填满磁盘、破坏主存储或修改访问控制；这类破坏性故障使用自动化注入验证。逐项操作步骤和当前结论见[手动测试指南](手动测试指南.md)，跨设备矩阵见[跨设备验证清单](cross-device-validation.md)。

## 文档与本地化同步

- 用户可见文本必须同步维护 `locales/zh-Hans.json` 和 `locales/en.json`；扩展清单文案同步维护 `locales/extensionJson/`。
- 用户功能、使用方式或限制变化时，同步更新 `README.md` 与 `README.en.md`。
- 发布行为和版本变化同步更新 `CHANGELOG.md` 与 `CHANGELOG.en.md`。
- 架构、协议、数据格式、测试结论或宿主边界变化时，更新对应 `docs/` 文档，不让 README 承载内部实现流水。
- README 中面向扩展广场的图片路径保持 `images/xxx.png`；其他仓库文档链接使用可从扩展广场打开的 GitHub 绝对地址。

文档只记录已经确认的行为。过时的设计或测试说明应明确标记历史状态、归档或删除，避免与当前实现并存而误导后续维护。

## 商城发布检查

发布或重新上传扩展前检查：

1. `extension.json` 包含名称、UUID、显示名称、描述、版本、许可证、仓库、至少一个分类和有效入口；不同 UUID 不复用相同 `name`。
2. `extension.json`、`package.json`、`package-lock.json`、README 安装包名和 CHANGELOG 版本保持一致。
3. 使用原创自定义 Logo，不使用 SDK 默认图。Logo 为清晰的 PNG 或 JPEG，建议 1:1，至少 `200x200`，不超过 5 MiB。
4. README 详细说明普通用户能理解的功能、安装、操作方式和重要限制；CHANGELOG 说明本版变化。
5. 审核包中的功能截图只使用虚构演示数据，不包含订单号、UUID、时间、批次指纹、电话、地址或其他隐私信息。
6. README 本地图片使用已经过商城验证的 `images/xxx.png` 形式，不使用 `./images/...`；上传前确认图片确实包含在 `.eext` 中。
7. 执行完整验证和构建，检查 `build/dist/` 中目标扩展包的文件名、清单、入口、图片和大小；不要上传诊断构建或本地测试数据。

扩展审核元数据约束由 `tests/unit/extension-review-metadata.test.ts` 持续校验，但最终仍需检查生成包内容和商城实际展示。
